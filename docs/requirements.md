# RepoDesk 需求文档

**状态：**讨论稿，基于截至 2026-11-09 的沟通整理。尚未确认的事项标注为“待讨论”。

## 1. 产品概述

RepoDesk 是面向 Windows 的多仓库 Git 管理桌面应用。用户指定一个或多个存放 Git 项目的目录，通过统一控制台查看多个仓库的状态，并对单个仓库或一组选定仓库执行常用操作。

核心价值是跨项目集中查看和批量管理，不是重新实现一个完整的单仓库 Git 客户端。

## 2. 用户与使用场景

- 用户在 Windows 电脑上管理多个本地 Git 项目。
- 用户打开应用后，希望快速知道哪些项目有未提交修改、待推送提交、远程更新或需要人工处理的分支状态。
- 用户希望对单个项目或多个项目执行 Fetch、Pull、Push 等操作，并查看每项操作的结果。
- 用户可能在多台设备上使用应用；代码交接通过项目现有的远程 Git 仓库完成。

## 3. 完成态目标

应用成熟后，用户可以：

1. 配置一个或多个项目根目录，发现并组织其中的 Git 仓库。
2. 在总览中了解整体待办，并在全部项目页搜索、筛选和选择仓库。
3. 查看每个仓库的工作区状态、当前分支、远程跟踪状态、提交差异及最近检查结果。
4. 对单个仓库查看改动、分支和提交，并执行常见 Git 操作。
5. 对多个仓库执行批量操作，查看成功、跳过和失败原因。
6. 查看操作历史，并管理扫描目录、默认 Git 提交身份及应用偏好。

## 4. 页面结构

已初步确定五个主要入口：

1. **总览**：全局状态摘要和待处理提醒。
2. **全部项目**：仓库搜索、筛选、排序和多选批量操作。
3. **项目操作**：当前选中仓库的改动、分支、提交历史及项目级操作。
4. **操作记录**：单项目和批量任务的进度、结果与错误详情。
5. **设置**：项目目录、扫描规则、全局默认 Git 提交身份及应用偏好。

“项目操作”依赖当前选中的仓库，不是脱离项目的通用页面。

## 5. 状态信息

仓库列表和详情应逐步支持展示：

- 项目名称、路径、当前分支和远程地址。
- 工作区是否干净，以及未提交或暂存的改动。
- 本地领先、落后远程的提交数量；已同步、仅需拉取、仅需推送或已分叉。
- 最近提交时间与摘要。
- 最近一次远程检查时间、操作状态和错误信息。
- 合并、变基等需要处理的仓库状态。

状态至少应能区分：已同步、需要拉取、需要推送、已分叉、有未提交修改、检查失败或检查结果可能过期。

## 6. 操作原则

- 启动后扫描仓库并检查远程状态；通过 Fetch 获取远程信息，不自动改写工作文件。
- 拉取和推送可按项目执行，也可对所选仓库批量执行。
- 批量同步先检查仓库状态。只自动执行可明确判断安全的操作；遇到未提交修改、分叉或冲突风险时跳过并说明原因。
- 不静默覆盖或重置用户的本地内容。可能丢弃或覆盖数据的操作必须清楚说明影响。
- 操作结果应按仓库记录成功、跳过或失败原因，并提供可查看的日志。
- 远程认证沿用本机 Git for Windows、Git Credential Manager 或 SSH 的配置。

## 7. Git 身份与认证

提交署名（`user.name`、`user.email`）与远程认证是两件事。应用需要显示有效署名配置，并考虑全局默认值和仓库级覆盖。远程推拉认证继续交给本机 Git 凭据管理或 SSH。

## 8. 范围状态

以下属于完成态讨论方向，不能据此视为首期承诺：仓库分组与标签、收藏、复杂分支管理、提交与暂存编辑、冲突辅助、定时刷新、多个根目录及细粒度扫描规则。

## 9. 待讨论事项

- 扫描目录由用户在设置中选择；默认最大递归深度为两层，用户可调整。常见依赖与构建目录会排除。
- 仓库发现后是否自动加入，仓库移动或暂时不可用时如何处理。
- “全部更新”的准确语义和分叉、脏工作区的交互细节。
- 项目详情页的具体布局、提交/暂存/撤销等操作的完成态范围。
- 首期版本范围与各功能优先级。
- 技术细节、数据存储方案、安装与更新方式。

# RepoDesk 设计文档

**状态：**初步方案；以 `wiki/` 中确认的决策为准。未定事项请勿当作实现约束。

## 1. 产品形态

- 目标平台：Windows 桌面应用。
- 产品正式名称：RepoDesk。
- 中文描述：多仓库 Git 控制台。
- 界面标语候选：所有项目，一屏掌握。
- 应用以独立桌面窗口运行，不要求用户通过外部浏览器访问。

## 2. 技术路线

当前倾向 Electron：复用 HTML/CSS/JavaScript 原型，由 Electron 主进程通过 Node.js 在本机访问文件系统并调用已安装的 Git。尚未创建应用骨架，此路线仍可在实现前调整。

初步分层：

- **渲染进程**：呈现总览、全部项目、项目操作、操作记录和设置页面。
- **主进程**：处理窗口生命周期、仓库扫描、Git 子进程、本地持久化及操作日志。
- **预加载桥接**：向界面暴露有限且明确的应用接口。
- **Git**：调用本机 Git for Windows；远程凭据交由 Git Credential Manager 或 SSH。

界面不直接执行任意命令。Electron 界面与本机能力之间使用受限接口；实现时遵循 Electron 当前安全建议。

## 3. 导航与页面职责

采用桌面窗口固定侧边导航，右侧内容区随窗口大小变化：

- 总览：展示全局摘要、待处理提醒和最近操作。
- 全部项目：展示仓库列表、搜索筛选和批量选择。
- 项目操作：聚焦选中的仓库，提供仓库详情和项目级操作。
- 操作记录：展示任务队列、执行进度、结果和错误信息。
- 设置：管理扫描目录、默认 Git 身份和应用偏好。

窗口不依赖固定宽高比；最大化和常见桌面窗口尺寸下均应可用。原型可先按 1440×900 设计，并验证 1280×800 下主要内容可用（此尺寸来自此前讨论，后续仍可调整）。

## 4. 仓库状态模型

视图应将两类信息分开展示：

- **工作区状态**：未提交修改、暂存修改、合并/变基状态等。
- **远程比较状态**：本地与跟踪分支的 ahead/behind 计数及同步关系。

执行 Fetch 后更新远程比较信息。网络不可用或远程检查失败时保留错误和检查时间，提示信息可能过期。

## 5. 批量操作交互

批量任务按仓库逐项执行并持续反馈状态。每个项目记录待执行、执行中、成功、跳过或失败及原因。开始前基于当前状态生成可执行项和需人工处理项；执行中不以某个仓库的失败掩盖其他结果。

“全部拉取/全部更新”仅对能够安全快进的仓库自动执行；有未提交修改、分叉或潜在冲突的仓库应跳过并解释。具体策略和交互待讨论。

## 6. 本地数据与安全边界

此前讨论过用 SQLite 保存项目目录、分组、界面偏好和操作记录；这只是候选设计，尚未确认。Git 仓库本身仍是代码状态的权威来源，应用不另行复制仓库内容。

本地 Git 命令应由主进程以参数数组启动，避免把用户输入拼成 shell 命令。后端接口应限制可调用的操作和路径范围，并将操作输出用于日志和错误说明。具体实现细节在技术设计阶段确定。

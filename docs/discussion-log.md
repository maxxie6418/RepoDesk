# 沟通记录

记录已发生的重要讨论和结论。详细且当前有效的决策请同时维护在 `../wiki/`。

## 2026-11-09：项目背景迁入 RepoDesk 仓库

- 用户使用 Windows，希望统一管理指定文件夹中的多个 Git 项目。
- 核心需求是打开应用后查看本地提交/工作区和远程更新情况，并对单个或所有项目快捷拉取、推送。
- 产品定位为跨项目统一控制台，而非单项目 Git 客户端。
- 用户提出先梳理完成态，再讨论首期版本。
- 初步页面结构：总览、全部项目、项目操作、操作记录、设置。
- 初步技术方向讨论为 Electron，便于复用 HTML 原型并访问本机 Git；尚未开始实现。
- 产品名暂定 RepoDesk。
- 用户要求创建 `docs/`、`wiki/` 和代码入口目录；项目资料按本次整理落盘。

## 文档维护

- 记录新的重要沟通，不必逐字抄录每条消息；保留需求变化、决定及未决问题。
- 结论确认后更新对应 wiki 页面，并在本记录中追加日期和变更摘要。

## 2026-11-09：名称与界面原型

- 用户确认 RepoDesk 为正式名称。
- 根据五个页面和已有需求创建桌面窗口 HTML 界面原型，使用演示数据。

## 2026-11-09：仓库扫描设置

- 用户确认仓库扫描目录由用户在设置中选择。
- 默认最大扫描深度为两层；深度可在设置中调整。
- 首阶段扫描只读取本地仓库状态，不执行 Fetch、Pull、Push。

## 2026-11-09：项目快捷操作与收藏备忘

- 总览与全部项目列表提供单项目远程刷新、快进拉取、推送、打开目录、备忘和收藏快捷入口。
- 拉取前执行 Fetch，并仅在工作区干净且可快进时执行；推送前 Fetch 并拒绝远程领先/分叉情况。
- 项目备忘和收藏路径保存到应用本机设置。
- 总览项目按最近提交时间倒序，并在底部单独展示收藏项目。

## 2026-11-09：单项目快捷操作与操作历史

- 列表中的远程刷新改为只检查当前仓库。
- Fetch、Pull、Push 的成功和失败记录写入本机操作历史，操作记录页读取显示。
- 每项 Git 操作按仓库逐条记录，最多保留 500 条。

## 2026-11-09：项目备忘存储方式

- 用户要求可选择将备忘保存在本机，或保存在各项目根目录的 `list.md`。
- 设置切换时迁移当前扫描到的仓库备忘；项目文件模式仅维护 list.md 中 RepoDesk 标记的区块。

## 2026-11-09：项目冻结远程检查

- 用户要求可单独设置项目“不关注/冻结”，跳过该项目的远程更新检查。
- 冻结只跳过远程 Fetch，不隐藏本地仓库、文件改动或提交信息；解除后需重新检查远程状态。

## 2026-11-09：批量安全同步与版本号

- 总览和全部项目页增加批量拉取、批量推送，自动跳过不符合安全条件的仓库并汇总结果。
- 项目版本更新为 0.2.0。
